# Помічник для опису фотографій

Локальний застосунок на HTML, Tailwind CSS, TypeScript та Vite. Оберіть встановлену модель Ollama з підтримкою зображень, прикріпіть фотографію й отримайте короткий опис українською. За замовчуванням обирається gemma3:4b (Q4_K_M).

## Запуск

Потрібні Node.js, npm і запущена Ollama. Завантажте модель:

    ollama pull gemma3:4b

Відкрийте термінал у теці цього проєкту:

    npm install
    npm run dev

Відкрийте адресу, яку покаже Vite. Ollama має працювати на http://127.0.0.1:11434. Запити /ollama/* пересилаються туди проксі Vite, тому додаткове налаштування CORS не потрібне. Проксі міститься у vite.config.ts.

Перевірка збирання та перегляд зібраної версії:

    npm run build
    npm run preview

Проксі налаштовано для обох команд запуску. Якщо роздавати dist/ іншим сервером, потрібно налаштувати аналогічний проксі або прямий доступ браузера до Ollama.

## Робота

1. Дочекайтеся завантаження списку моделей. За замовчуванням вибрано gemma3:4b, якщо вона встановлена.
2. Оберіть модель із підтримкою зображень. Список містить усі встановлені моделі, зокрема текстові, тому підтримку фото перевіряйте в описі моделі.
3. Прикріпіть JPG, PNG або WebP розміром до 10 МБ та перевірте попередній перегляд.
4. Натисніть «Створити опис». Під час очікування показується індикатор, повторне надсилання заблоковане.

Фото передається як Base64 Data URL через OpenAI-сумісний POST /v1/chat/completions. Список моделей отримується через GET /v1/models. Історія попередніх запитів не додається. Фото не зберігається застосунком на диск.

## Параметри генерації

- temperature: 0.2 — невисока випадковість для предметного опису.
- max_tokens: 300 — обов’язкове обмеження довжини відповіді. Якщо воно досягнуте, інтерфейс попередить про можливе обрізання.
- seed: 1 — фіксований seed для порівнюваних запусків; абсолютна відтворюваність залежить від рантайму.
- stream: false — відповідь показується цілком, під час генерації є індикатор очікування.
- Рекомендований контекст — 4096 токенів. Він задається в Ollama (наприклад, через Modelfile з PARAMETER num_ctx 4096), а не полем max_tokens. Клієнт не перевизначає контекст; фактичне значення можна перевірити командою ollama ps.

Для запиту до моделі встановлено таймаут 120 секунд. Показуються повідомлення про недоступну Ollama, помилки моделі, пошкоджений файл, таймаут і некоректну відповідь. Перевіряйте описи: модель може помилятися в деталях та українській граматиці.
